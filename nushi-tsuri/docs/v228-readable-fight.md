# v228：ぬし釣り式の入力猶予と離す予兆

糸の緩みを認識してAを押すころには、ナマズの520〜820msの隙が終わって走りへ戻ることがあった。海王の竿でも600msの入力待ちを加えたv227の普通ナマズ3条件は600秒で寄せ切れなかった。素早い自動操作で勝利が成立する確認だけでは、読み取って操作する余裕の確認になっていなかった。

## 操作の流れ

1. 魚が走る間はAを離して待つ。
2. 糸が緩んだらAで引く。緩みの受付は最低1800ms。
3. 正しい新しい押下には最低1200msの引ける時間を確保する。
4. 尾の動きが強まり、魚の縁と糸が淡い橙色になったらAを離す。次の走りまで900msの予兆がある。
5. 走る前に離せた引きの成果は、次の走りを正しくいなす間も残る。

受付時間と引く時間は同時に進み、最後に予兆が続く。120ms周期の処理で表示されるため、切り替えは次の周期で処理される。具体的な時間は本作の調整値であり、『ぬし釣り64』の内部計算の再現として断定しない。

## 制約と既存機能

- 一つの隙で受付を延長するのは最初の正しい押下だけ。連打で期限を更新し続けられない。
- 前の走りからAを押し続けても、そのまま隙の引きに移行しない。一度離して新しく押す必要がある。
- 予兆中は追加で寄せられない。走る魚を引いた場合の張力上昇・後退と、離すのが遅れた場合の後退は残る。
- ボスの段階変更とヒラメの砂底からの抜け出しは、進行中の引きと予兆を中断せず、次の動きへ予約する。
- エラ洗い後も同じ受付・引く・予兆の処理を使う。アプリの背景移行では押下を解除し、復帰時に各期限を同じだけ延ばす。
- ぬし釣り式の説明文とAボタンの表示をそろえ、引けない状態で巻くように促す共通文を使わない。成功した引き以外では成功を示す巻き音を鳴らさない。
- 竿の性能、魚の抵抗、サイズ倍率、弱い竿ではぬしを寄せ切れない上限を保持する。独立した時間経過の疲労は今回追加していない。
- ゲージ式の計算・タイミング、釣果の登録・保存、湿地と魚種、船と水面、将来のFT・時間調整・終盤装備・DLCは変更しない。

## 再現検査

`tests/nushi-playability-v228.test.cjs` は実ゲームのDOM、自然な動き選択、120ms処理、押す／離す、移動とlanding判定で確認する。画像の描画だけ省略し、ファイトの寄せ率や張力を成功値へ変更しない。海王の竿と適切な餌・ハリを使い、普通／巨大のナマズ・コイ・ライギョ・星湖のヌシ・星降るヌシを、入力待ち600ms×乱数3条件で検査する。普通ナマズには待ち0／360msの比較もある。

追加の検査は、遅い正しい押下、連打、押しっぱなしの失敗、正しく離した成果、離すのが遅れた場合、背景移行、ボスの段階変更。湖ぬしと星降るぬしは解放条件を分けたテスト用セーブを使い、出現しない魚を後から差し替えない。

`tests/browser-v228.fight.cjs` はPC1280×720のマウスと横画面844×390のブラウザタッチ入力で、合法な投点の選択から投げ込み・アワセ・ファイト・自然な釣り上げ・保存・再読み込みまで確認する。ぬし釣り式は600msの入力待ち、ゲージ式の比較は待ち0ms。時計を進める検査であり、実機Androidで人が遊んだ検証として扱わない。スクリーンショットと各条件の記録はCIの `nushi-browser-evidence` に残す。

## 原典

1998年の『ぬし釣り64』説明書19ページの「逃げる間は待つ、糸の緩みを見て引く、暴れる前に離す、繰り返して寄せる」という操作を参考にした。[説明書掲載ページ](https://gamemanual.midnightmeattrain.com/entry/%E3%81%AC%E3%81%97%E9%87%A3%E3%82%8A64)。説明書は受付時間や疲労の内部計算を示していない。
