# Issue #269: 餌ゼロ時の釣り準備とフィールド復帰

対象基点: `f87b28158a5b128323fefaa2fed589b61d2760a2`。

## 原因

釣りの準備段階のBは「仕掛け変更」で、仕掛け画面を閉じても同じ準備画面へ戻るだけだった。フィールドへの終了操作は投点選択へ進んだ後のBにしかなく、開始できない装備では戻る道が分かりにくくなっていた。餌切れ時の開始処理には、釣り画面の破棄と店・犬の救援への切替も混在していた。

## 修正

- 餌が一つもなく、既存の銀のスプーンとルアーロッドも所持していなければ、フィールドからの入場を止めて短い案内を出す。既存の犬の救援はフィールドで維持する。
- 使用できるルアー装備があれば、餌ゼロでも準備へ入れる。現在エサ釣りを選択中なら、既存のB・仕掛け画面からルアーへ切り替えられる。自動で装備を変えない。
- 準備画面と仕掛け画面に「フィールドへ戻る」を設ける。終了処理は開始条件を検査せず、既存の終了処理で入力・音・タイマー・画面を片付ける。準備画面でのEscape／戻るでも終了できる。
- Bの仕掛け変更、仕掛け画面を閉じて準備へ戻る操作、ファイト中のBによる糸出しは維持する。
- 準備後・投げる直前に餌やルアーがなくなったら、開始・投げ直しだけを拒否し、案内と戻る操作を残す。店などへ強制切替しない。
- 最後の餌を既に投げた一投はそのまま続ける。餌・時間の消費は従来どおり投げる時に一度だけ。進行中の一投を開始ボタンで作り直せないようにする。
- 未所持の竿、無効な装備ID、餌とハリの不整合を開始前に確認する。表示のフォールバックは在庫や選択IDを書き換えない。旧セーブの装備補完は既存の正規化を利用する。

セーブキー・形式・バージョン・魚種・釣り条件・店や地図は変更しない。配信キャッシュだけを `252-3` に更新する。

## 検証

修正前にPC1280×720・タッチ844×390でB→仕掛けを閉じる→戻るを操作し、準備画面へ留まることを再現した。

`cast-cancel-269.test.cjs` は、入場防止、ルアーの可否、画面内の餌切れ、複数の戻る経路、最後の一投の消費、装備不整合、旧セーブ・別スロット、無料練習を確認する。

`browser-cast-cancel-evidence.cjs` は、PC1280×720・スマホ相当844×390・820×366/DPR1.875で同じ操作を行う。スマホ条件では実際のtouchポインターイベント、44px以上の主要ボタンの画面内配置、保存再開も検証する。専用CIはマージ後に公開ランタイム6ファイルのSHA-256を照合し、公開URLでも同じ操作を行う。画面とログはCIの証跡へ保存する。

既存の釣り・アワセ・釣果・ルアー・大会・セーブ・店・移動は、従来の回帰テストも利用する。今回、チュートリアルや新機能は追加しない。
