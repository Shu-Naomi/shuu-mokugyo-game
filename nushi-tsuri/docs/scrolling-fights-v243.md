# v243：水中の移動感と、引ける隙の手応え

直美の実プレイでの「背景をループして距離と逃走を感じたい」「引けるタイミングが来ても少し引くとすぐ魚の番になる」を受けた調整。基準は改修仕様書保存版5の第1・3章と、『ぬし釣り64』の原本説明書18〜19・24ページ。

## 参考にした流れ

- 魚が走る間は引かずに待ち、落ち着いて糸が緩んだら引く。再び暴れる前に離す。
- ルアーは巻く・止めるで誘い、反応した魚を見て食いつかせ、アワセをする。
- 元の説明書は左への逃走・右への取り込み。本作の向きは最新仕様書どおり右への逃走・左の水面への取り込みを維持する。
- 以下の秒数・巻速・スクロール量は本作の調整値。原作の内部計算やフレーム数の再現とは扱わない。

原本スキャン：[釣りの基本18〜19ページ](https://cdn-ak.f.st-hatena.com/images/fotolife/j/jackallsasaki/20220227/20220227001337.jpg)、[ルアー24ページ](https://cdn-ak.f.st-hatena.com/images/fotolife/j/jackallsasaki/20220227/20220227001353.jpg)。[所蔵元の記事](https://gamemanual.midnightmeattrain.com/entry/%E3%81%AC%E3%81%97%E9%87%A3%E3%82%8A64)。原作の画像はゲーム素材へ取り込まない。

## 今回の動き

| 場面 | 調整 |
| --- | --- |
| 逃走 | 背景の岩・水草を左へ流し、右へ泳ぐ魚を追う。画面端に着いても背景が途切れず移動感が続く |
| 巻き寄せ | 背景を逆へ流す。ルアーの誘い中も、巻いた距離で同じ水中背景が進む |
| 接続 | 食いつき・アワセ・ファイトでカメラ位置を保ち、背景を初期位置へ戻さない |
| 一周 | 既存の水中画を隣で左右反転して継ぎ、往復どちらでも切り替えの段差や空白を作らない。魚・針・糸・UIは動かす背景から分離 |
| 引ける隙 | 入力を待つ緩みは最低3秒。正しくAを押した時点から最低3.6秒は引ける。押し直しても締切を延々と補充しない |
| 離す予兆 | 1.2秒。初めて予兆を表示してから確保し、遅れた更新で予兆を飛ばさない |
| 魚の走り | 最低2.1秒、魚種の元の時間に合わせ最大4.2秒。短い状態の高速切り替えを抑える |
| 残距離 | ぬし釣り式の魚の泳げる範囲を残距離に合わせて水面へ狭める。0mでも画面全体の遠くへ逃げ続ける表示を防ぐ |
| ルアーの接近 | 止めたスプーンに約2秒かけて追いつく。速巻きのままでは追いつけず、約7.2秒追って離れる。現れた魚を見て巻く・止めるを選べる間を作る |
| 背面・動きを減らす設定 | 背面中はカメラも停止。復帰で時間をまとめて進めない。動きを減らす設定ではスクロールせず従来の背景を使う |

カメラの移動量は表示専用で、実際のメートルや魚の個体、釣果、所持品、消費時間を変更しない。逃走中の横方向の追尾と、糸が巻き取られる距離は別の値として扱う。ゲージ式の餌釣りは今回の背景スクロールの対象外。ゲージ式でルアーを選んだ場合は、誘いからファイトまで同じ背景移動を使う。

## 検証

- `scrolling-fights-v243.test.cjs`：遅い入力でも一回の隙でまとまった距離を寄せられること、予兆を飛ばさないこと、ルアーの追跡、正逆・一周の背景の画素の充填と一致、背面復帰、表示用カメラと実際の釣りデータの分離、残距離に応じた泳げる範囲。
- `nushi-playability-v228.test.cjs`：600ms遅れた入力、大型個体・ヌシ、押しっぱなしでは勝てないこと、初期竿制限など既存の駆け引きを継続確認。
- `browser-v243.fishing.cjs`：PC1280×720、タッチ844×390・820×366（DPR1.875）×両ファイトの6組。マウス／タッチの誘いから自然な取り込み、保存再読込まで確認。背景の方向・停止・アワセ時の連続、約3.6秒の引き、魚と針・糸の接点、画面端と操作ボタン上の表示域を検査する。抽選・開始セーブ・時計は固定し、ファイト中の釣果や取り込み率は書き換えない。

最終結果と公開確認はPR・WORK引き継ぎへ記録する。タッチ想定ブラウザの検証は直美の携帯実機での体感確認とは区別する。
