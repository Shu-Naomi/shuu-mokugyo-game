## 目的と提案値

世代をつないだ魚から、まれに特別な色の子が生まれる楽しみを加える。見た目と発見記録を中心にし、体長上限、成長、経験値、星、売値、コンテスト得点への変異ボーナスは付けない。真エンドや既存図鑑の完成条件、DLC購入条件には組み込まない。

| 項目 | 次回の初期案 | 状態 |
| --- | --- | --- |
| 解放 | **誕生する子が3代目以降** | 内部値は子の `generation >= 2` |
| 出現率 | 対応魚の新しい卵1組につき0.1%（1/1000） | 調整可能な提案値 |
| タイミング | 卵を生成するとき、一度だけ | 通常色だった結果も保存 |
| 種類 | 黄金・白化・蒼鱗など、魚種ごとの対応表 | 全魚種の採用を確定しない |
| 遺伝 | 初期案ではしない | 変異した親からも同じ独立確率 |
| 発見 | 孵化したとき、小さな演出と記録 | 卵の時点では結果を明かさない |

0.1%では、対象の卵693組ほどで「一度以上出る確率」が約50%、2995組ほどで約95%。1000組でも約63.2%で、必ず出るわけではない。既存の産卵3日・孵化2〜4日・水槽定員と合わせると非常に長期の収集になる。率や救済制度の変更は、実装前に別途判断する。今回、確率上昇や確定枠を勝手に追加しない。

## 既存実装の事実

根拠は `pet-life.js` の `normalize` / `sync` / `acquire` / `lifeStage`、`aquarium-life.js` の `appearance` / `decorate`、`index.html` の `petCatalog` / `save()`、`save-slots.js`。

| 既存構造 | 設計への影響 |
| --- | --- |
| 飼育データは `petLife.version = 5`。魚と卵の正規化は保存項目を明示的に組み立て直す | 未対応の変異項目を追加するだけではロードで消える。次PRで両方の正規化・互換処理が必要 |
| 購入個体の世代は0。子は `min(20, max(母の世代, 父の世代) + 1)` | 初代=0、2代目=1、**3代目=2**。両親が3代目になるまで待つ仕様にはしない。表示の上限は21代目 |
| 同魚種の成魚オス・メスを、水質・元気・給餌条件を満たして3日世話すると産卵 | この条件と進行を維持する。性別は現在UIDから補完される場合もあり、今回の表示変更で繁殖条件を変えない |
| 卵1レコードから子1匹。卵の画像に描く5粒は装飾 | 抽選は1レコード1回。粒ごとの5回抽選ではない |
| 空き定員は卵が予約。孵化待ちや移動後にも `sync` が走る | 孵化延期・再同期・描画時の再抽選は禁止 |
| 孵化日数はヤマメ・ニジマス4日、コイ・フナ・ホンモロコ2日、その他3日 | 変異でも維持 |
| 卵は親UIDを保存していない。繁殖進捗には親UIDがある | 卵生成時に親の識別子を記録する案。抽選キーと検査の根拠にする |
| セーブは状態全体のJSON。現状、繁殖専用の永続乱数種はない | 「ロード前後で同じ卵に同じ結果」を保証する仕組みを追加する必要がある |
| 通常水槽6槽×5匹、ぬし専用2槽×8匹 | 定員を増やして確率を埋め合わせない。ぬしは現状繁殖対象外 |
| 世代は星の成長間隔・買い取り・コンテストにも使う | 表示世代や抽選条件のために既存の世代値をずらさない |

産卵時の健康条件は元気70%以上、水質68%以上を検査してから一晩の水質低下を適用する。画面の育て方にある水質目安と混同して、その周辺を今回書き換えない。

### 世代の具体例

| 母 | 父 | 子の内部値 | 子の表示 | 0.1%案の対象 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 1 | 2代目 | 対象外 |
| 1 | 0 | 2 | 3代目 | 対応魚なら対象 |
| 1 | 1 | 2 | 3代目 | 対応魚なら対象 |

### 既存の成長外観との共存

- ブリはモジャコ→ワカシ→イナダ→ワラサ→ブリの名前・体長条件と、3系統の原画を使う。変異IDは個体に残し、段階が変わっても対応色の原画へ切り替える。80cmの繁殖条件も維持する。
- ニジマスのパーマークから赤帯への変化、イサキの幼魚の縞から成魚への変化は既存の成長表現。突然変異や新発見扱いにしない。
- `appearance` の成長段階選択を先に行い、その結果へ対応する変異原画を選ぶ構成が候補。`decorate` の幼魚表現と重なる部分を検証する。
- 水槽全体やDOM全体のCSS色相回転は使わない。他の魚・背景・文字を変えず、魚の輪郭、姿勢、口、アンカー、透明度を維持する。

## 保存と抽選の契約案

次PRではスキーマを明示的に更新する（案: `petLife.version = 6`）。現行UI PRでは更新しない。

| 保存対象 | 次PRの項目案 | 保証したいこと |
| --- | --- | --- |
| 冒険ごとの繁殖抽選種 | `mutationSeed`、抽選ルール版 | セーブ1・2を分け、卵ができる前から保存しておく |
| 新しい卵 | `mutation: {checked: true, kind: "normal" または対応ID, ruleVersion: 1}`、親UIDのスナップショット | 通常色の結果も保存。判定済みと未対応の旧卵を区別 |
| 孵化した魚 | 卵からコピーした変異結果 | 体長・水槽・星・レベルが変わっても維持 |
| 発見記録 | 魚種・色ID・初発見日と通知済み状態 | 同じ孵化の再ロードで演出を繰り返さない |

`kind` は表示名でなく安定したID（例: `gold`）にする。未知の将来IDは落とさず保持し、表示だけ通常原画へ安全にフォールバックする案。魚・卵の両 `normalize` と保存再開試験で確認する。卵から魚へコピーする項目を明示し、親の `mutation` を子へ無条件コピーしない。

### ロードによる引き直しを防ぐ範囲

「卵を作るときにランダム判定して保存」だけなら、卵を保存した後のロードには耐えるが、**産卵前のセーブへ戻る**と別の結果を引ける。この差を隠さない。

推奨案は、冒険開始または互換移行時に一度用意して保存する種と、卵UID・親UID・産卵日・魚種・ルール版から決定的な抽選値を作る方式。同じ保存地点から同じ組み合わせの卵を作り直しても同じ結果になる。ゲームが通常のセーブを完了する前に種を再生成しない。種の保存失敗時は抽選を確定扱いにせず、既存の未保存表示と整合させる。

現在の `sync` は同期関数で、ロード時にも呼ばれる。非同期のWeb Crypto処理をその場に差し込むと進行と衝突する。種の準備をロード後の初期化段階で済ませ、卵生成では同期の決定的関数を呼ぶ案が適合する。具体的なハッシュ・乱数方式は次PRで、注入可能な抽選器とともに決める。0〜999の均等な整数の0を当選とする設計なら、32ビット値の単純な剰余による偏りにも対処する。

通常のロードによる引き直し対策であり、セーブJSONの手編集、異なる日や親での別の卵まで同じ結果に固定する仕組みではない。旧セーブのコピーが種の導入前に作られている場合、そのコピー間の同一性までは復元できない。

### 旧データの互換方針

1. 既存魚は通常色として読み、後付け抽選しない。既存の世代・成長・性別・星・卵数を変えない。
2. 既に存在する卵は通常色・旧記録として扱い、孵化時の抽選をしない。
3. 対応外魚、初代・2代目の新しい卵も通常色を保存し、将来の対応追加で再抽選しない。
4. 抽選済み結果とルール版は、正規化・水槽移動・成長・買い取り画面・保存再開の経路で保持する。
5. 今回UIが使う欠損表示メモは表示専用。繁殖や抽選の真偽判定に流用しない。世代欠損を高世代へ推定する移行も行わない。

## 必要な素材と小さな発見演出

パイロット魚の通常原画を基準に、既存アニメーションの方向・折り返し・口の開閉を網羅した対応原画、透明度、輪郭、描画アンカーをそろえる。稚魚から成魚まで通常原画と同じサイズ倍率で表示する。ブリへ広げる段階ではモジャコ・若魚・ブリの3原画系統と全成長境界が追加で必要になる。

黄金・白化・蒼鱗の文字ラベルを一覧・詳細・記録に添え、色だけで区別させない。孵化時の小さな光と短い一文、発見記録を候補にする。強い点滅や長いモーダルで日常の世話を止めない。動きを減らす設定を尊重し、通知済みフラグを保存する。収集記録は釣った魚の図鑑・本編達成条件から分離する。

## 今回の表示PRとの境界

今回のUIは保存済みの性別と世代を表示するだけ。欠損のある旧記録は「性別不明」「世代不明」と表示する。既存コアが欠損値を補完するため、同じ端末・セーブ内でその欠損の由来を表示専用メモへ残す。魚・卵・セーブJSONの形式には項目を追加しない。

このメモはセーブ番号と個体の安定した識別情報で分離し、成長や水槽移動で失われないようにする。ブラウザの表示メモを消した場合、または別端末へ補完済みJSONだけを移した場合、もともとの欠損を復元できない。既に明示的な値として保存されていた性別・世代は、その値を表示する。これは現在の表示互換性の限界として記録し、推測の系譜を生成して補わない。
