# v242: 仕様書に沿ったぬし釣り式とスプーン

基準は「星降る湖_改修仕様書_2026-09-28.md」保存版5、たたき台v0.6（9月29日更新）の第1・3・8章。今回の範囲は水中ファイトとルアーの操作・表示・一投の確定。仕様書の竿重複管理、犬の部門、繁殖などを新たに変更する作業ではない。

## 操作と表示の対応

| 仕様 | 今回整えたところ |
| --- | --- |
| Aを短く押してもスプーンを誘える | 押して離すまでが120msの更新間隔より短くても、一回分の入力を次の更新へ渡す。長押しの自動反復は新しいタップに数えない。背面移行時には未処理の入力を取り消す |
| 食いつきが表示されてからアワセを受け付ける | 最初に食いつきを表示した時刻から猶予を数える。処理が遅れて最初の表示前に失敗することを防ぎ、表示を初めて出したA操作をそのままアワセに流用しない |
| 新しいA入力でアワセし、その押下を引きへ重ねない | 誘い・食いつき・アワセ・選んだファイトを分ける。押しっぱなしでは自動成功せず、アワセ後も一度離してからファイトの入力を受け付ける |
| 魚と距離を引き継ぐ | 投点の0〜100の目盛りとメートル表示を区別する。スプーンの距離を実際のキャスト距離に合わせ、巻いた分の残距離と食いついた位置からファイトを始める。魚種・サイズは抽選し直さない |
| 魚が右へ逃げ、糸の緩む隙に左の水面へ寄せる | ぬし釣り式の通常の逃走中は、元の位置へ戻す水平の力で魚が左へ滑らないようにする。深く潜る魚やゆっくり泳ぐ魚でも、右への逃走表示と移動を一致させる |
| 魚と糸を見て判断できる | 緩み・引ける時・暴れる予兆に合わせて糸の形を更新する。物理更新を待たず、最初の描画から緩み／張りの表示を揃える。CSSで移動・旋回中の実際の魚の位置に針と糸を追従させ、接点を別々に遅れて補間しない |

追ってきた魚は、口がスプーンへ触れた位置から引き継ぐ。手前の食いつきでも元の投点へ跳ね戻さず、追っているヒラメはすでに砂底から離れている状態にする。

ぬし釣り式の右端には、魚の表示サイズ・傾き・個体倍率の分の余白を取る。魚の頭が画面外に欠けたまま走り続ける表示を防ぐ。

## 維持すること

- 水中ファイト方式は一投の開始時に確定する。魚の候補・サイズの抽選と、釣果・図鑑・大会・保存は共通。
- ルアーは「誘う → 興味を示した魚が登場 → 食いつき → 新しいAでアワセ → 選択したファイト」。全候補の魚影を常時並べる機能は加えない。
- スプーンは従来どおり再利用でき、餌と針を追加消費しない。一投10分・大会の投数・報酬を、誘い・アワセ・中断で二重計上しない。
- アプリが背面へ移った間は動きとアワセ猶予を止める。復帰時に長押しと未処理タップを解除する。
- 走る魚を引けば張力が上がり、糸が緩んだ時だけ寄せられる。初期竿のヌシ制限と、上位竿でも引く／離すの判断が必要な仕組みを維持する。

アワセ猶予は通常1.5秒、試し釣りは2.8秒を引き継ぐ。スプーンは最大巻速で一更新120msあたり0.08m進む初回調整。速度・誘引量・距離や猶予の細部は、仕様書にある通り最終確定の数値として扱わない。参考作品の内部処理を再現したと主張しない。

## 検証

- `fishing-spec-v242.test.cjs`: 短タップ、未表示の食いつき、アワセと引きの分離、背面復帰、距離・個体・位置の引き継ぎ、全魚の逃走方向、最初の糸の緩みを検査する。
- `ui-fish-sync.test.cjs`: 遅延した初回表示と、表示後の有効／無効なA入力を検査する。従来の「未表示のまま時間切れ」という期待値を仕様書の条件へ更新する。
- `nushi-playability-v228.test.cjs`、`coast-nushi-v213.test.cjs`: 遅れての操作・大型個体・ヌシの取り込みと、長押しだけでは勝てないことを確認する。
- `browser-v242.fishing.cjs`: 実際のマウス／タッチ操作でスプーンを短く誘い、接近・食いつき・背面復帰・アワセ・両ファイト・取り込み・保存復帰まで確認する。ファイト中に釣果や取り込み率を直接書き換えない。抽選と時計は検証用に固定する。

PC1280×720、タッチ844×390と820×366（DPR1.875）を対象とする。実行結果と公開の確認はPRに記録し、タッチ想定ブラウザを直美の携帯での実機確認済みとは扱わない。
