# 育成魚の愛称 — v252-11

基点main `aed39b2e0b8d86b0ee8b0da87e6eb18fee22b225`。拡張草稿5.3・6.1の個体別の命名を、育成ノートと水槽の既存個体へ追加する。

## 操作

育成ノートの個体を選び、上部の「愛称を付ける／愛称を変更」から入力する。水槽の「記録・管理」からも同じ画面を開ける。対象の魚種と個体番号、性別と世代を確認してから保存できる。

主人公・ワンコと同じ `player-options.js` のUnicode処理を使い、1〜12文字を受け付ける。結合文字・絵文字のまとまりを数え、NFC正規化と制御文字除去を共有する。空欄で保存すると愛称を外して魚種名の表示へ戻る。入力の上限512コード単位も既存画面と揃える。未入力の旧個体に名前を自動配布しない。

編集画面の背後をinertにし、Tabの移動とEscapeを画面内で扱う。日本語変換中のEnterやEscapeでは保存・画面閉鎖を行わない。通常のEscape・「やめる」では入力を捨て、元の個体・ページへ戻る。入力中とキャンセル時はセーブしない。保存失敗時は元の愛称へ戻し、入力を保って再試行できる。同じ愛称の保存では書き込みを増やさない。

## 個体と保存の契約

- 任意フィールド `petLife.fish[].nickname` のみを追加。`petLife.version=6`、`petNotebook.version=1` を維持する。旧個体で愛称がなければフィールドを増やさない。不正な型・長すぎる値・空の保存値は採用しない。
- 魚種・成長段階を表す `displayName` と、愛称を優先する `individualName` を分ける。画面では魚種名と個体番号も残す。ブリが出世しても愛称は維持し、成長段階の名前は更新される。
- 編集・移動・買い取り・託す対象は変更不能のUIDで判定する。同じ愛称を複数個体に付けても別個体のまま。ノートの表示個体を改名しても、水槽側で選択中のUIDを変更しない。
- 愛称による能力・価格・品評会点・希少色の補正はない。変異ルール1、種、抽選キー、確率、成長・繁殖条件を変えない。親に愛称があっても子へ同じ名前を自動継承しない。
- 品評会は受付時の愛称を記録し、後日の改名で過去の受付・結果を書き換えない。長い絵文字をコード単位で切らず、12文字の名前を保存再開でも維持する。対象魚種・参加個体は別のIDで保持する。
- 愛称はゲーム内の表示文字列としてエスケープする。水槽全体のaria-labelも含め、HTMLや属性として解釈しない。別セーブ、他個体、釣果、所持金、所持品を変更しない。

現役個体への愛称が今回の範囲。手放した個体の台帳、父母の名前履歴、能力遺伝、レースは後続の設計とする。
